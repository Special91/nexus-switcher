## 2024-06-25 - Custom i18n System lacks ARIA Label Support
**Learning:** The application uses a custom localization system (`applyTranslations()` in `app.js`) that translates elements via `data-i18n` and `data-i18n-title`. However, it did not process localized `aria-label`s. This led to icon-only buttons missing screen-reader accessible names because developers couldn't easily localize them using the existing HTML attributes pattern. Similarly, interactive state toggles (like view modes or game booster processes) didn't dynamically convey their states (`aria-pressed`, `aria-checked`, `role=switch`).
**Action:** Extended the localization system to process `data-i18n-aria-label` attributes. Next time I work with a custom i18n system, I should immediately verify if it supports translating essential accessibility attributes and implement them if they are missing to ensure developers can easily build accessible UI components.
